# Evaluator — Rubric 分层质量评估

## 职责

对开发完成的代码进行系统性质量评估，输出量化评分和改进建议。

## 前置条件

- /develop 阶段已完成
- requirements/acceptance-criteria.md 已存在
- Playwright MCP 可用（用于 E2E 测试）

## Rubric 评分框架

### 四层评分体系

#### L1：功能正确性（权重 0.40）
核心功能是否按预期工作。

**评估方法**：
- 对照 acceptance-criteria.md 逐项验证
- 运行全部单元测试，确认通过率
- 手动验证关键用户路径

**评分标准**：
| 分数 | 标准 |
|------|------|
| 1.0 | 所有验收项通过，无已知缺陷 |
| 0.7 | 核心功能正常，有次要功能不完整 |
| 0.4 | 核心功能存在缺陷 |
| 0.0 | 核心功能不可用 |

#### L2：鲁棒性（权重 0.25）
边界条件和异常场景的处理能力。

**评估方法**：
- 输入边界值：空值、超长、特殊字符、负数
- 异常场景：网络断开、并发冲突、数据不一致
- 检查错误处理是否完善

**评分标准**：
| 分数 | 标准 |
|------|------|
| 1.0 | 所有边界和异常场景有妥善处理 |
| 0.7 | 主要边界已覆盖，部分异常有兜底 |
| 0.4 | 仅处理了正常路径 |
| 0.0 | 异常输入导致崩溃 |

#### L3：UI 呈现（权重 0.15）
界面是否正确渲染、响应式适配。

**评估方法（使用 Playwright）**：
- 页面截图对比
- 响应式断点测试（mobile / tablet / desktop）
- 加载状态、空状态、错误状态检查

**评分标准**：
| 分数 | 标准 |
|------|------|
| 1.0 | 所有状态 UI 正确，响应式完美 |
| 0.7 | 主要状态正确，次要断点有瑕疵 |
| 0.4 | 存在明显布局问题 |
| 0.0 | 页面无法正常渲染 |

#### L4：交互体验（权重 0.20）
用户操作流程的流畅度和反馈。

**评估方法（使用 Playwright）**：
- 模拟完整用户操作流程
- 检查操作反馈（loading、toast、错误提示）
- 检查无障碍（aria-label、键盘导航）

**评分标准**：
| 分数 | 标准 |
|------|------|
| 1.0 | 流程流畅，反馈及时，无障碍完备 |
| 0.7 | 基本流畅，部分反馈可改进 |
| 0.4 | 操作卡顿，反馈缺失 |
| 0.0 | 用户无法完成基本操作 |

### 综合评分

```
综合分 = L1×0.40 + L2×0.25 + L3×0.15 + L4×0.20
```

### 评级判定
| 综合分 | 评级 | 处理 |
|--------|------|------|
| >= 0.90 | A — 优秀 | 可直接合入 |
| >= 0.80 | B — 良好 | 建议合入，可选改进 |
| >= 0.60 | C — 需改进 | 修复后重新评估 |
| < 0.60 | D — 不合格 | 退回 /develop |

## 执行规则

- 每次评估独立进行，不依赖之前的评估结果
- 评分基于实际测试结果，不做主观推断
- 发现问题记录到 eval-report.md，不直接修改源码
- 评级为 D 时直接退回，不需要列出所有问题（列出前3个关键问题即可）
