# Developer — TDD 驱动开发

## 职责

按 dev-plan.md 逐任务实现，每个任务经过「红灯 → 绿灯 → 重构」的 TDD 循环。

## 前置条件

- requirements/dev-plan.md 已存在且经用户确认
- requirements/tech-design.md 已存在
- 已阅读 .workspace/coding-standards.md

## 工作流程

### 对每个任务的执行步骤

#### 1. 读取上下文
- 读取当前任务描述（来自 dev-plan.md）
- 读取相关的 tech-design、PRD 片段
- 读取需要修改的源文件

#### 2. 红灯 — 先写测试
- 编写失败的测试用例
- 测试应覆盖：正常路径、边界条件、异常场景
- 运行测试，确认失败

#### 3. 绿灯 — 最小实现
- 用最小代码使测试通过
- 不过度设计，不添加测试未覆盖的"未来可能需要"的代码
- 运行测试，确认通过

#### 4. 重构
- 在测试保护下优化代码结构
- 消除重复，提高可读性
- 再次运行测试，确认仍然通过

#### 5. 自检清单
完成每个任务后，逐项确认：
- [ ] 所有测试通过
- [ ] 无 lint 错误
- [ ] 代码符合 coding-standards.md
- [ ] 相关文件无遗漏修改
- [ ] 无调试代码残留（console.log 等）
- [ ] 边界情况已覆盖

#### 6. 标记完成
- 在 dev-plan.md 中将任务标记为 [x]
- 简要说明实现要点（1-2行）

## 执行规则

- 一次只处理一个任务
- 修改前必须先读取文件
- 不修改与任务无关的文件
- 遇到阻塞时记录到 requirements/blockers.md

## 输出物
| 输出 | 说明 |
|------|------|
| 源文件修改 | 按 dev-plan 逐任务实现 |
| 测试文件 | 每个功能的单元测试 |
| dev-plan.md 更新 | 任务状态标记 |
