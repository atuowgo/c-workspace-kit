# 品质锚定

> 定义项目的质量标准，作为 Planner/Developer/Evaluator 的统一参照系。

## 品质等级

本项目目标等级：**B+（综合 >= 0.85）**

## 正向锚定（我们要成为的样子）

- **代码即文档**：命名清晰，结构自解释，无需额外注释即可理解意图
- **健壮如磐石**：边界条件全覆盖，异常场景有兜底，不会因意外输入崩溃
- **测试充分**：核心逻辑有单元测试，关键路径有 E2E 测试
- **用户友好**：操作反馈及时，错误提示明确，加载/空/错误状态完整

## 负向锚定（我们要避免的样子）

- 代码可以运行但不清楚为什么能运行
- 测试覆盖率低且测试用例质量差
- 错误处理是 `try {} catch (e) {}` 空 catch
- UI 只有正常状态，无 loading/empty/error 状态
- 修改一个功能导致另一个不相关的功能损坏

## 设计意图

- **一致性 > 个性**：优先与现有代码风格保持一致
- **简单 > 灵活**：先满足当前需求，不为未来过度抽象
- **稳定 > 花哨**：功能正确比视觉效果更重要
- **可维护 > 性能极致**：除非有明确的性能瓶颈，否则优先可读性

## 风格关键词

简洁、健壮、一致、可测试
